# kaspernissen.xyz — portfolio site design

**Date:** 2026-05-01
**Owner:** Kasper Nissen

## Purpose

A personal showcase for Kasper Nissen — talks, writing, conferences, presentation decks, speaker photos, badges, and live GitHub activity — discoverable by peers in the cloud-native community. Booking-oriented content (speaker kit) is included but not the lead.

## Goals

- One canonical home for everything Kasper has shipped publicly: YouTube talks, blog posts, podcast appearances, slide decks, conference appearances, professional badges, GitHub activity.
- Stays fresh **without manual upkeep for sourced content** — nightly cron rebuilds pull from APIs and redeploy.
- Manual entries (curated talks, invited keynotes Sessionize doesn't know about, hand-written bios) coexist with sourced ones and always win on conflict.
- Static, fast, free to host. No server runtime, no per-visitor API calls.

## Non-goals (v1)

- No CMS / no admin UI. All content is YAML or Markdown in the repo.
- No comments, no newsletter signup, no contact form. Email and socials are enough.
- No multi-language. English only.
- No analytics in v1. (Trivial to add later if Kasper wants Plausible/Umami.)
- No search. The lists are short enough that a `Cmd+F` is fine.

## Architecture

### Stack

- **Astro 5** (static site, content collections, `<Image>` for responsive images)
- **Tailwind CSS 4** (via Astro integration)
- **TypeScript** for fetcher scripts and component props
- **GitHub Pages** with custom domain `kaspernissen.xyz` (CNAME committed in `public/CNAME`)
- **GitHub Actions** for build + deploy (push trigger + nightly cron)

### Data flow

1. GitHub Action triggers (push or nightly cron).
2. `npm ci` then `npm run prebuild`, which runs all five fetcher scripts in parallel.
3. Each fetcher writes typed YAML files under `src/content/<collection>/<source>/` (talks/conferences/writing/badges) or JSON under `data/` (GitHub heatmap — too high-cardinality for collections).
4. Astro builds (`astro build`) producing static HTML/CSS/JS in `dist/`.
5. `actions/deploy-pages@v4` deploys `dist/` to GitHub Pages.

Manual entries are never touched by fetchers. Auto entries land in subfolders so they can be wiped and rewritten on each run without affecting curated content.

## Content collections

Each collection has a Zod schema in `src/content/config.ts` enforced at build. Schemas:

### `talks/`
```yaml
title: string                     # required
event: string                     # required
date: date                        # required, ISO
location: string                  # optional
abstract: string                  # markdown, optional
youtube_id: string | null         # nullable
slides_pdf: string | null         # /decks/<file>.pdf path
co_speakers: string[]             # default []
tags: string[]                    # default []
featured: boolean                 # default false
```

### `decks/`
```yaml
title: string
event: string
date: date
file: string                      # filename within public/decks/
talk_slug: string | null          # cross-link to a talk
size_mb: number | null            # auto-filled by a build helper
```

### `conferences/`
```yaml
name: string
date: date
end_date: date | null
location: string
url: string
role: 'speaker' | 'co-chair' | 'organiser' | 'mc' | 'attendee'
session_title: string | null
```

### `writing/`
```yaml
kind: 'blog' | 'podcast' | 'newsletter' | 'interview'
title: string
publication: string
date: date
url: string
duration_min: number | null
summary: string | null
```

### `speakers/` (photos)
```yaml
slug: string
caption: string
event: string
date: date
photographer: string
license: string                   # SPDX-style or freeform
src: string                       # ./<file>.jpg under src/assets/speakers/
download: string                  # /speakers/<slug>-fullres.<ext>
```

### `badges/`
```yaml
name: string
issuer: string
issued: date
url: string
image: string                     # path under src/assets/badges/<slug>.png
```

### Slug generation

Auto-generate from `title + date` (e.g. `from-zero-to-production-with-otel-2025-04`). `slug:` field overrides if set.

### Sort order

`date desc` for everything except `conferences` filtered to upcoming, which uses `date asc`.

### Manual-wins merge rule

When fetched and manual entries point at the same logical item:
- **talks**: matched by `youtube_id` (if present on manual entry) OR by Levenshtein title similarity (>0.8). On match, the fetcher merges its `youtube_id` into the manual entry instead of writing a new file.
- **conferences**: matched by `(name, date)` tuple. Manual entry wins all fields.
- **writing**: matched by `url`. Manual entry wins.

## Integrations

### YouTube Data API v3
- Playlist ID: `PL5T4q56AEyfVPQUu4R6ESZfIT-gq8AYw1`
- Endpoint: `playlistItems.list` with `part=snippet,contentDetails`, paginate `pageToken`.
- Per video: title, description, publishedAt, video ID.
- Title heuristic to extract event (parses common patterns like "Talk Title — KubeCon EU 2025").
- **Secret required:** `YOUTUBE_API_KEY` in GitHub Actions.

### Sessionize
- Public speaker API: `https://sessionize.com/api/speaker/<speaker-id>/sessions` — returns JSON.
- Maps to conferences with `role: speaker` and `session_title`.
- **Open question:** Sessionize speaker ID — derive from Kasper's public Sessionize profile URL (TBD: needs URL or ID).

### Credly
- Public profile API: `https://www.credly.com/users/kasper-nissen/badges?sort=most_recent` returns HTML; JSON endpoint at `/badges.json` is the reliable one.
- Downloads each badge image into `src/assets/badges/<slug>.png` so Astro can optimize.
- No auth required.

### GitHub
- **Profile README** (`github.com/kaspernissen/kaspernissen`): fetch `README.md` raw, parse markdown links under known section headers (TBD: confirm section names like `## Blog`, `## Podcasts` — fetcher checks Kasper's actual README structure on first run).
- **Contributions heatmap**: scrape `https://github.com/users/kaspernissen/contributions` (the public SVG/HTML endpoint GitHub renders for profile pages). Parse into `{date, count, level}` array. Render as inline SVG at build via the `GitHubHeatmap.astro` component.
- **Pinned repos**: GitHub GraphQL `user(login).pinnedItems` — optional, used in landing page "what I'm building" strip.
- **Auth:** GitHub token recommended for higher rate limit (`GITHUB_TOKEN` is auto-provided in Actions).

## Visual style — "playful / cartoon-forward"

- Type: `Inter` (sans, weights 400/500/700/800), system fallback.
- Palette:
  - background: `#fffaf0` (warm off-white)
  - ink: `#1c1917` (near-black)
  - accent: `#fb923c` (orange-400) — used sparingly on key phrases & active states
  - secondary accent: `#fde68a` (amber-200) for highlights
  - subdued: `#78716c` (stone-500) for meta text
- Highlight motif: rotated colored block behind selected words in headlines (the "I talk cloud." treatment from style C).
- Cards: white background, 2px black border, soft drop shadow, slight rotation on hover.
- Pills for tags/socials: black fill, white text, rounded-full.
- Cartoon hero image is the visual anchor; tilted ~2° to feel less stiff.

## GitHub Actions

### `deploy.yml`
- Trigger: push to `main`.
- Steps: checkout → setup-node → `npm ci` → `npm run build` (which runs `prebuild` fetchers) → `actions/upload-pages-artifact` → `actions/deploy-pages`.

### `refresh.yml`
- Trigger: cron `0 3 * * *` (nightly 03:00 UTC) + `workflow_dispatch`.
- Steps: identical to `deploy.yml`. The fresh fetch happens automatically because `prebuild` runs the fetchers.
- Concurrency: single in-flight build (cancels previous nightly if it overlaps).

### Secrets required
- `YOUTUBE_API_KEY` — Kasper to create in Google Cloud Console and add to repo secrets.
- `GITHUB_TOKEN` — auto-provided.

## Failure modes

- **Fetcher fails (API down, key invalid)**: script exits with warning, build continues using whatever YAML files already exist on disk in the auto-source subfolder. Stale-but-shipping is preferred over a failed deploy. Each fetcher logs its outcome to a build summary line.
- **YouTube quota exhausted**: fetcher detects 403 quota error and exits cleanly; cached entries remain.
- **GitHub contributions scrape format changes**: fetcher fails loud (build fails). The heatmap is high-visibility on the landing page; we want to know fast.
- **Custom domain / DNS misconfig**: pre-deploy step verifies `public/CNAME` content matches `kaspernissen.xyz`. DNS is owned outside the repo (Kasper's registrar).
